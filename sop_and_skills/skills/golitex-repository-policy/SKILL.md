# golitex-repository-policy

This is the imported maintainer profile for the golitex repository. Read
[the detailed working agreements](references/golitex-agents.md) completely
before taking actions there; live repository AGENTS.md and direct user
instructions take precedence. It does not impose golitex's local workspace or
publication layout on unrelated Litex projects.

Protected AST, Env and Runtime changes require concrete user authorization.
Keep accepted Session work across an ordinary failed statement. Follow
impact-based gates, source-owned journals, draft/public boundaries and the
local-only scripts rule. Read [task SOP and evidence promotion](references/task-sop.md)
for substantive implementation work and
[the explicit-proof boundary](references/search-explicit-proof-boundary.md)
when assessing search misses.

The [source guide](references/source-guide.md) retains the original policy
entrypoint. CLI syntax and output are owned by the target version's
[CLI reference](../../references/litex/docs/cli.md).

## Execution and scope

Use [the current execution contract](../litex-reference/references/execution.md)
and the target version's Manual and CLI. Repository rules in the imported notes
apply inside golitex; outside that repository use the owning project's paths
and user-authorized trust policy. Existing skill references are conditional
reading routes, not instructions to load every skill.
